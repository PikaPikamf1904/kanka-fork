# Kanka-CE and Trail-Code review

Reviewed 2026-10-16 against `develop` (`c700f4651`) and the `bigbertha/self-hosting` deploy kit.
Sources: `Kanka-CE/kanka-community-edition` (`nightly`), `Kanka-CE/kanka-ce-deploy` (v0.12, LGPL-2.1),
`Kanka-CE/docker-kanka-ce`, `trailhq/Trail-Code` (MIT, 0.23.0). Nothing from them was run.

## Verdict

**Keep our native Debian deployment. Borrow two ideas from Kanka-CE, re-implemented and tested here.
Adopt none of its code or containers.**

## Version compatibility

Kanka-CE `nightly` is upstream Kanka as of 2026-09-14 plus its patch commits. Our `develop` is newer
(2026-09-23). PHP 8.4, Laravel 13, Livewire 3 and Pest 4 constraints are identical, so nothing in CE
is needed to run on Big Bertha.

## Container stack vs ours, on a 4 GB dual-core

| | Kanka-CE deploy | Our kit |
|---|---|---|
| Processes | Docker daemon, app (nginx + PHP + memcached, s6), MariaDB 11, Redis, Meilisearch | nginx, PHP-FPM, MariaDB, 2 queue workers, scheduler timer |
| Idle memory (rough) | Meilisearch alone wants 0.5–1 GB; plus Docker and Redis | well under 1 GB total |
| Published ports | 80, **3306**, **6379** (Redis, no password), **7700**, all interfaces | 22 and 80 only; MariaDB on loopback/socket |
| DB root | `MYSQL_ROOT_HOST: '%'` | socket auth only |
| Default secrets | `password` until `gen-passwords.sh` runs; leaves a `.bak` with old values | generated by `provision.sh`, `.env` mode 600 |
| Starts after reboot | no `restart:` policy | systemd units, `Restart=always` |
| Queues | one worker as root, only if configured; `sync` by default | `default` and `heavy` workers as `kanka` |
| Scheduler | none (so no backups, no cleanup) | systemd timer every minute |
| Backups | none | encrypted nightly + pre-migration, restore script |
| Updates | `migrate --force` on every container start, no backup first | build → backup → migrate → health check → automatic rollback |
| Build | latest GitHub tag at build time, `npm install --legacy-peer-deps` | from our commit and lockfiles |
| Analytics | Meilisearch analytics on unless disabled | none |

The container approach costs more memory, exposes more ports and has weaker update safety.

## CE patches

| Patch | Decision |
|---|---|
| `Enable-Premium` (boosts = 100, subscriber = true) | **Rejected.** Bypasses premium entitlements. |
| `Add-optional-invite-password` | **Idea adopted**, rewritten: constant-time compare, throttled, off by default. |
| `user:add` artisan command | **Idea adopted**, rewritten: uses Kanka's own user creation, no hard-coded role ids. |
| Email try/catch, `APP_EMAIL_ENABLED` | Not needed: we use `MAIL_DRIVER=log`. |
| Stop mailing `hello@kanka.io` | Not needed now: those mails only fire on Stripe events, and mail is log-only. Flagged. |
| `TZ` timezone, default mail address | Skipped; config already covers it. |
| `EntityEventTypes::none = 1` | Not needed: fresh installs seed ids 2–5 only; id 1 exists only in old imported data. |
| MinIO filesystem | Not needed: local disk. |
| Font Awesome swap (`fa-duotone` → `fa-solid`) | Later, as a CSS fallback. CE's kit route needs a fontawesome.com account, which we avoid. |

## Trail-Code

A local code map (tree-sitter, PHP supported) that Claude Code reads through hooks. The map needs no
API key; `--deep` summaries need your own key.

Reasons not to install it into this repo now:

- **Public repo.** `trail init` suggests committing `.claude/`, `.mcp.json` and `.trail/`. Learnings
  drawn from sessions could carry infrastructure or campaign details into a public repo.
- **Global hooks.** It also writes hooks and a skill under `~/.claude`, which run in every folder.
- **Telemetry on by default.** The npm `postinstall` sends an install event unless `DO_NOT_TRACK=1`
  or `CI` is set.
- **Reads history.** It reads past Claude Code transcripts for the repo and recent PR review comments.

Expected benefit is modest on this codebase. If you want to try it, do it in a throwaway container on
a copy of the repo, with telemetry off and `--dry-run`, and never commit what it creates. See
`deploy/dev/README.md`.
